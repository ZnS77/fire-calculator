# FIRE 计算器

算的是一件具体的事：**按你现在的存钱速度，最早哪一年可以不干了 —— 并且撑到最后还留得下救命钱。**

和常见 FIRE 计算器的三点不同：

| | 常见做法 | 这里 |
|---|---|---|
| 退休年龄 | 你填，程序告诉你够不够 | **解出来**：扫描每一个可能的年份，返回第一个可行的 |
| 死亡年龄 | 固定，或隐含 100 年 | **可拖动的输入**，并有专门一张图展示「多活十年要多干几年」 |
| 终局资产 | 归零即可（余额转负才算失败） | **必须 ≥ 你设定的应急预留金**，且这笔钱按医疗通胀而非 CPI 滚动 |

## 快速开始

```bash
npm install
npm run release    # 类型检查 + 84 项测试 + 生产构建（压缩 + 内容哈希）
open index.html    # 双击就能开，不需要服务器
```

日常开发：

| 命令 | 作用 |
|---|---|
| `npm run build` | 开发构建，不压缩、保留注释 |
| `npm run build:prod` | 生产构建，压缩到约 35 KB |
| `npm run watch` | 增量重建 |
| `npm run check` | 类型检查 + 全部测试 |
| `npm run release` | `check` + `build:prod`，发布前跑这个 |
| `npm run serve` | 本地 http://localhost:8080 |

### 关于构建产物

`js/app.js` 是**提交进版本库的构建产物**，GitHub Pages 直接推上去即可，不需要跑 CI。

`build.mjs` 会把 `js/app.js` 与 `css/style.css` 的内容哈希戳进 `index.html` 的引用上
（`?v=aa2358b8`）。这不是装饰：静态托管会缓存这两个文件，
**改了样式却看到旧版本**是开发过程中真实踩过的坑 —— 内容变了 URL 就变，缓存自然失效。
脚本会先剥掉旧哈希再写新的，可重复执行。

### 运行时依赖

零。打包成单个 IIFE，`file://` 双击和 HTTP 托管都能跑。

唯一的外部请求是 Google Fonts（IBM Plex Sans / Mono、Source Serif 4）。
拿不到时会回退到系统字体栈（苹方 / 宋体 / SF Mono），页面照常可用，只是观感差一点。

`src/types.ts` 里的 branded type 不是装饰。这个模型有二十多个数值参数，全是 `number`，

## 模型

### 逐年名义模拟

全部用名义金额推演，展示时再折算成今日购买力。这样才能同时表达多条互不相同的通胀轨道
（年支出 3.2% / 医疗 6% / 养老金上调 2%），恒定购买力口径做不到。

```
期末 = 期初 × (1+r) + 净现金流 × √(1+r)
```

**年中约定**：现金流按年中发生，只吃半年收益。参考实现普遍假设现金流年初一次到位、
吃满全年收益，会系统性高估，储蓄额越大高估越多。

另外两条约定：

- t=0 那年的支出**恰好等于**输入的年支出，不预先乘一次通胀
- 支出分段区间左闭右开，年龄正好等于段起点时归属新段

### 求解

从当前年龄线性扫描到死亡年龄，返回第一个满足「全程不破产 且 死亡年末资产 ≥ 预留金」的年份。

**必须线性扫描，不能二分。** 时间轴事件（养老金、买房、子女教育）会破坏单调性。

养老金与 FIRE 年龄互相依赖（停缴年龄决定养老金，养老金又影响能多早退休），用两轮迭代取不动点，
实测即收敛。

### 实际收益率用除法

```
实际收益率 = (1 + 名义) ÷ (1 + 通胀) − 1
```

`r − i` 是近似式，误差 = `i·r/(1+i)`。r=7%、i=2.5% 时精确 4.39% vs 近似 4.50%，
40 年终值差约 4.5%。代码里一律用除法。

### 退休后的支出曲线

Blanchett (2014, *Journal of Financial Planning*) 的实证：退休后**实际**支出在第一个十年年降约 1%、
第二个十年年降约 2%、之后年降约 1%，到 84 岁累计约 **−26%**，此后回升。

关键：他测的是**总**实际支出，医疗上涨已被可选支出（旅行、社交）的下降抵消在内。
所以本模型**不在支出上再叠加医疗通胀**，那是双重计算。医疗通胀只用在应急预留金上。

Bernicke (2005) 给出更激进的 −3.7%/年，但那是**横截面**数据（不同年龄的不同人），
当作同一个人的时间轨迹有世代效应问题（Tharp, SSRN）。本模型以 Blanchett 为准。

> **这些数据全部来自美国。** 中国本土的退休支出年龄曲线未找到实证研究，
> 所以做成默认可关闭的开关，关掉即按恒定实际购买力计算。

### 应急预留金按医疗通胀滚动

```
目标名义金额 = 预留金 × (1 + 医疗通胀)^年数
```

这笔钱的用途是大病自付，不该按 CPI 滚。人均卫生总费用 2015 年 2,952 元 → 2024 年 6,454.4 元，
年化 **9.1%**（含用量增长与老龄化，属上界），默认取 6%。

后果是反直觉的：今天的 50 万，65 年后按 6% 是名义 **2,180 万**。只显示「留 50 万」是在骗自己。

### 安全提取率对照线是动态的

4% 法则出自 Bengen (1994) 与 Trinity Study (1998)，前提是 **30 年**期限、美国 20 世纪数据、
50–75% 股票、忽略税费、终值归零。40 岁退休活到 90 岁是 **50 年**，超出适用范围一倍。

| 退休年数 | 建议提取率 | 出处 |
|---|---|---|
| 30 年 | 3.5%（原始 4%，Morningstar 2025 前瞻 3.7%） | Trinity 1998 |
| 40 年 | 3.25% | Pfau、Kitces 延长测试 |
| 50–60 年 | 3.0% | ERN, SSRN 2920322（美国数据 3.5%，A 股波动更高再打折） |

ERN 的原话是「3.5% is the new 4%」。中文社群对 A 股建议 3%–3.3%。

## 社保养老金

```
基础养老金     = 计发基数 × (1 + 本人平均缴费指数) ÷ 2 × 缴费年限 × 1%
个人账户养老金 = 个人账户储存额 ÷ 计发月数
```

计发月数取国发〔2005〕38 号附件（60 岁 139，63 岁 117）。缴费基数钳在当地社平的 60%–300%。
个人账户按缴费基数的 8% 逐年入账并按记账利率复利。

过渡性养老金仅对有视同缴费年限者（一般 1996 年前参加工作）适用，本模型不计 —— 目标用户基本不在此列。

### 记账利率做成了联动参数，不是常数

人社部历年公布值：

| 2016 | 2017 | 2018 | 2019 | 2020 | 2021 | 2022 | 2023 | 2024 | 2025 |
|---|---|---|---|---|---|---|---|---|---|
| 8.31% | 7.12% | 8.29% | 7.61% | 6.04% | 6.69% | 6.12% | 3.97% | 2.62% | **1.50%** |

十年从 8% 级降到 1.5%，历史均值（约 5.8%）已完全失真。2016–2022 的高利率是与社平增长挂钩的
政策性定价，2023 年起转向市场利率锚。

诚实的做法不是猜一个绝对值，而是把它建成 **社平增长率 − 1.5pp** 的联动参数。
长期利率低于工资增长是结构性的，这正是「个人账户待遇被持续稀释」的机制来源 ——
用联动参数，调高社平增长时能自动看到稀释加剧；固定 5.8% 则会同时高估账户余额和替代率。

### 提前退休的约束

最低缴费年限不是永远 15 年。依《国务院关于渐进式延迟法定退休年龄的办法》第二条，
**2030 年起**由 15 年每年提高 6 个月，2039 年及以后为 **20 年**。

法定领取年龄：1976 年 9 月后出生的男性一律 63 岁，女干部 58，女工人 55（都已封顶，
目标用户基本落在封顶区）。

停止工作后两条路：

- **灵活就业续缴**：费率 20%（12% 统筹 + 8% 个人账户），全额自付
- **直接断缴**：已缴年限**不清零**（累计制），个人账户余额继续计息，
  平均缴费指数也**不受影响** —— 断缴年份不计入指数的分母。真正的损失只有缴费年限减少和账户停止新增

**事后一次性补缴基本已被堵死**（人社部发〔2016〕132 号：对灵活就业人员不得以事后追补缴费的方式
增加缴费年限）。「延长缴费 5 年仍不足 15 年可一次性补足」出自人社部令第 13 号第二条，
只对 2011-07-01 前已参保者开放。

## 已知局限

**最重要的一条：恒定收益率会系统性高估。**

真实世界存在**序列收益风险** —— 同样的平均收益，顺序不同结局不同；退休头几年遇上熊市，
一边跌一边取钱会永久锁死复利基数。

用中证指数 2005–2025 全收益数据做 bootstrap 重抽样（60/40 组合，实际年化 7.5%）：

| 期限 / 提取率 | 恒定收益率模型 | 实际成功率 |
|---|---|---|
| 30 年 / 4% | 存活，期末 4.30 倍 | 84.2% |
| 40 年 / 4% | 存活，期末 8.26 倍 | 79.2% |
| 50 年 / 4% | 存活，期末 16.42 倍 | **76.0%** |
| 50 年 / 3% | 存活，期末 21.60 倍 | 86.9% |

恒定收益率模型对 2.5%–5% 的**每一个**提取率都报「永不破产」，实际有 16%–36% 的路径破产。
这不是精度误差，是定性错误，且误差方向永远偏乐观。

另一个恒定模型完全看不见的效应：**降波动直接换成功率**。相同实际年化 4% 下，
30/70 组合 50 年成功率 70%，60/40 只有 55%。

> 计划中的下一步是加 bootstrap 成功率（5,000 条路径，参数化对数正态为主、历史块自助为辅），
> 引擎已经预留了 `simulate(input, retireAge, returnSeq)` 的注入钩子。

其他局限：

- 不含税
- 不模拟资产配置与再平衡
- 不含汇率与移居
- **医保未建模**。终身待遇年限因地而异（上海 15 年，北京男 25 女 20，多省正向男 30 女 25 统一），
  且断缴次月即停止统筹报销。对提前退休的约束往往比养老金更硬 ——
  养老金可以少领，医保是「要么一次性凑够换终身、要么每年买到死」

## 已修复的坑

开发过程中真实踩到、且已写进测试钉住的：

1. **个人账户历史回溯的循环方向反了** —— 最近一年的缴费被复利最久，显著高估账户余额
2. **记账利率默认 6% 高于社平增长 4%** —— 33 年下来账户跑赢工资基数，把替代率推到 99%
   （调研算例是 36.4%）。现已改为联动参数
3. **合并 CSS 时残留 `<style>` 标签** —— 把整个浅色 `:root` 变量块吃掉，
   导致 `stroke=""`，图表线条静默消失。`cssv()` 现已带兜底色
4. **重构时把 `--grid` 改名成 `--rule` 但图表代码没跟着改** —— 旧名只在浅色块里还在，
   深色模式下网格线取到浅色值。测试里加了三主题作用域的覆盖校验

缴费指数 = 本人缴费基数 ÷ 当年社平。主模型里工资到 45 岁封顶，而社平仍按 4% 增长，
所以**指数会逐年滑落**，基础养老金随之被拉低。这是模型必须传递 `capIncomeGrowthAt` 的原因 ——
漏传会让指数锁死在初值，系统性高估待遇（见「已修复的坑」第 5 条）。

界面上会显示指数的起止变化，以及是否撞上 300% 顶格上限（超出部分不计入养老金）。

恒定收益率模型对 2.5%–5% 的**每一个**提取率都报「永不破产」，实际有 16%–36% 的路径破产。
这不是精度误差，是定性错误，且误差方向永远偏乐观。

另一个恒定模型完全看不见的效应：**降波动直接换成功率**。相同实际年化 4% 下，
30/70 组合 50 年成功率 70%，60/40 只有 55%。

> 下一步计划加 bootstrap 成功率（5,000 条路径，参数化对数正态为主、历史块自助为辅，
> 及格线 85% 且不做成二元通过/失败）。引擎已预留
> `simulate(input, retireAge, returnSeq)` 注入钩子，不需要重构。

其他局限：

- 不含税
- 不模拟资产配置与再平衡
- 不含汇率与移居
- **医保未建模**。终身待遇年限因地而异（上海 15 年，北京男 25 女 20，多省正向男 30 女 25 统一），
  且断缴次月即停止统筹报销。对提前退休的约束往往比养老金更硬 ——
  养老金可以少领，医保是「要么一次性凑够换终身、要么每年买到死」

## 已修复的坑

开发过程中真实踩到、且已写进测试钉住的：

1. **个人账户历史回溯的循环方向反了** —— 最近一年的缴费被复利最久，显著高估账户余额
2. **记账利率默认 6% 高于社平增长 4%** —— 33 年下来账户跑赢工资基数，把替代率推到 99%
   （调研算例是 36.4%）。现已改为联动参数
3. **合并 CSS 时残留 `<style>` 标签** —— 把整个浅色 `:root` 变量块吃掉，
   导致 `stroke=""`，图表线条静默消失。`cssv()` 现已带兜底色
4. **重构时把 `--grid` 改名成 `--rule` 但图表代码没跟着改** —— 旧名只在浅色块里还在，
   深色模式下网格线取到浅色值。现有三主题作用域的覆盖校验
5. **工资封顶没传进养老金模块** —— 指数锁死在初值而非逐年下滑，系统性高估待遇
6. **预留金水位线画错了口径** —— 图上按面值画（50 万），而真实约束是
   `面值 × ((1+医疗通胀)/(1+CPI))^年数`（556 万）。等于拿两把尺子量同一条线，
   看起来像"结余比设定的多十倍"
7. **收入无天花板** —— 年薪 30 万按 4% 复利涨 30 年是 97 万、按 6% 是 172 万。
   现已加职业天花板（今日购买力，随通胀保值），并同步约束养老金的缴费基数
8. **`never` 情形差一年** —— 退休判定是 `age >= retireAge`，取 `retireAge = deathAge`
   会让最后一年仍算退休年，少算一年工资、报出的缺口偏悲观。应取 `deathAge + 1`

第 1、2、5、6 条都是「同为 number、单位却不兼容」造成的 ——
名义 vs 实际、比率 vs 百分数、今日购买力 vs 发生年份名义值。
这也是 `src/types.ts` 上 branded type 的由来。
